# Sheetdesk

macOS 카카오톡을 콘솔 형태로 읽고 직접 답장하는 로컬 터미널 앱입니다.
기본값은 **김도완과 이름이 일치하는 방만 표시**하며(공백은 무시하므로 `김 도완`도 포함), Codex 콘솔을 참고한 전체 폭 대화와 하단 `›` 입력창을 사용합니다.
다른 이름의 방으로 자동 대체하지 않습니다. `Ctrl+O`에서는 전체 대화방을 검색하고 선택할 수 있습니다. 기존 표/로그 화면도 옵션으로 남아 있습니다.
Python 표준 라이브러리(curses)와 [silver-flight-group/kakaocli](https://github.com/silver-flight-group/kakaocli)를 사용합니다.

## 실행

```sh
cd /Users/kookyungmin/workspace/sheetdesk
./run.sh --demo       # 합성 샘플로 UI 확인, 카톡 접근/전송 없음
./run.sh --doctor     # DB 접근 진단, 방 이름이나 메시지 본문은 출력하지 않음
./run.sh              # 김도완 방만 표시, 콘솔 화면, 2초 자동 조회
./run.sh "홍길동"     # 실행할 때 대화방 이름 지정
./run.sh "프로젝트 회의" # 이름에 공백이 있으면 따옴표로 감싸기
./run.sh --view log   # 로그 화면
./run.sh --view sheet # 이전 표 화면
./run.sh --readonly   # 읽기만 허용
./run.sh --room "김도완" # 표시할 방 이름 완전 일치. 이 옵션을 반복하면 여러 방 지정 가능
```

Finder에서 `Sheetdesk.command`를 더블클릭해도 실행됩니다. 터미널 창 크기는 105열 × 28행 이상을 권장합니다.

최초 빌드가 필요하면 `./setup.sh`를 실행하세요. Python 패키지 설치는 필요 없습니다.
설치 스크립트는 Homebrew SQLCipher와 동봉한 Swift 소스를 사용합니다.

현재 이 맥에서는 빌드와 계정 확인을 마쳤으므로 `./run.sh`로 바로 실행하면 됩니다.
실제 DB의 24개 방 조회와 메시지 20개 파싱을 확인했고, 한 번의 메시지 조회는 약 0.24초였습니다.
실제 발송은 하지 않았습니다. 자동 테스트 28개와 가상 터미널의 콘솔 화면·방 목록·샘플 왕복·가리기·종료를 확인했습니다.

## macOS 권한

시스템 설정 → 개인정보 보호 및 보안에서 **실행하는 터미널 앱**에 다음 권한을 부여하세요.

- **전체 디스크 접근**: 카카오톡 로컬 DB 읽기.
- **손쉬운 사용(접근성)**: 카톡 UI를 조작해 사용자가 확인한 메시지 전송.

권한 변경 후 터미널을 완전히 종료하고 다시 실행해야 할 수 있습니다.
카카오톡은 사용자가 직접 로그인하세요. 이 앱은 계정 비밀번호를 받거나 저장하지 않습니다.

## 조작

| 키 | 기능 |
| --- | --- |
| Ctrl+O | 전체 대화방 목록 열기/닫기. 이름 입력으로 검색하고 ↑↓·Enter로 선택 |
| ↑↓ | 콘솔 입력 중 대화 스크롤, 방 목록을 열면 방 선택 |
| Tab | 방 목록 / 대화 영역 전환 |
| / | 방 이름 검색 |
| i 또는 Enter | 답장 작성 (콘솔은 연결 후 바로 입력 가능) |
| 입력 중 Enter | 대상·창 상태 검사 후 바로 전송 (추가 확인 없음) |
| Esc | 입력 모드 종료 (초안 유지) |
| Ctrl+U | 입력 지우기 |
| Ctrl+B | 즉시 빈 콘솔로 가리기 / 복귀 (표 모드에서는 빈 표) |
| Ctrl+R | 즉시 새로고침 |
| Ctrl+T | 콘솔 / 로그 / 표 전환 |
| PgUp / PgDn | 대화 스크롤 |
| G | 최신 메시지로 이동 |
| Ctrl+Q 또는 Ctrl+C | 종료 (전송 중에는 완료 후 종료) |
| ? | 도움말 |

초안은 방별로 메모리에만 유지됩니다. 종료하면 사라집니다. 전송은 자동으로 재시도하지 않습니다.
메시지 전송이 실패하거나 시간이 초과되면 원래 카톡에서 전송 여부를 확인하세요. 재전송하면 중복될 수 있습니다.

## 자동 조회와 카톡 창

- 선택한 방의 최근 200개 메시지를 기본 **2초 간격**으로 읽습니다. 방 목록은 15초 간격으로 갱신됩니다.
- `--interval 3`처럼 주기를 바꿀 수 있습니다. 읽기 중에도 입력과 화면 가리기가 동작합니다.
- 화면을 가리는 동안 새 폴링을 시작하지 않습니다. 이미 진행 중인 조회/전송은 취소하지 않습니다.
- DB에 들어온 메시지는 방 창이 닫혀 있어도 읽을 수 있습니다.
- 실시간 수신은 맥 카톡의 DB 동기화에 의존합니다. 맥 카톡을 실행·로그인 상태로 유지하세요.
- 오래 열지 않은 방은 카톡에서 한 번 열어야 최신 대화가 동기화될 수 있습니다.
- 읽기만으로 새 대화를 서버에서 가져오지는 않습니다. 모든 방의 완전한 실시간 수신을 보장하지 않습니다.
- **앱 시작과 전송 전에 카톡을 숨깁니다.** 앱 활성화·창 앞으로 정렬·창 열기·전역 키 입력을 하는 전송 경로를 사용하지 않습니다. 입력 포커스 지정 전후와 전송 대기 중에 실제 `isHidden` 상태를 확인하며 숨김이 풀리면 다시 숨기고 중단합니다. 실제 메시지 발송의 종단 검증은 아직 하지 않았습니다.
- 숨김 플래그뿐 아니라 WindowServer의 화면상 카톡 창 개수도 확인합니다(제목이나 화면 내용은 수집하지 않음). 동봉한 CLI에서는 이전 앱 코드가 `--background` 없이 호출해도 전면 전송으로 대체하지 않습니다. 새 화면의 상단 버전은 `0.3.0`입니다.
- 열려 있는 여러 대화 창 중 **이름이 일치하는 대상 창 하나만** 선택합니다. 다른 방의 새 메시지나 알림 창이 생겨도 첫 번째 창에 보내지 않습니다. 말풍선 영역을 입력창으로 잘못 인식하지 않도록 편집 가능한 입력칸만 찾습니다.
- 처음 한 번 대상 대화 창을 열어두면 됩니다. 앱이 자동으로 카톡을 숨기고 입력 포커스를 지정하므로 **입력칸을 매번 클릭할 필요는 없습니다.** 읽기에 창이 필요한 것은 아니지만, 숨김 상태 전송에는 기존 대상 창이 필요합니다. 창을 새로 여는 경로는 사용하지 않습니다.
- **Enter를 누르면 대상 방 입력칸에 남아 있는 내용은 새 메시지로 교체합니다.** 초안이 있다는 이유로 차단하지 않습니다. 키 전송 전에 실패하면 입력칸이 여전히 앱이 쓴 내용일 때만 원래 값을 복원합니다. Return 전달 이후 결과가 불명확하면 자동으로 다시 보내지 않습니다.
- 사진·동영상·이모티콘은 종류 또는 저장된 텍스트로 표시하고 이미지로 렌더링하지 않습니다.
- 이름 없는 방 및 같은 이름의 방은 전송을 차단합니다. 카톡에서 고유한 방 이름을 지정하세요.

## 전송 오류 진단

오류 안내 문구 자체는 셸 명령어가 아닙니다. 다음 명령으로 읽기 전용 진단을 실행하세요.

```sh
./run.sh --doctor
```

진단은 카톡 실행 여부·손쉬운 사용 권한·채팅 목록 접근·지정한 이름 일치를 확인합니다.
창을 열거나 메시지를 보내지 않고, 대화 내용도 출력하지 않습니다.
손쉬운 사용 권한이 없으면 **실제 앱을 실행하는 Terminal/iTerm 등의 앱**을 시스템 설정에서 허용하고 완전히 종료 후 다시 실행하세요.
DB 읽기 권한과 전송에 필요한 손쉬운 사용 권한은 서로 다릅니다.
백그라운드 전송 준비 상태도 함께 표시합니다. 대상 창과 이름을 확인하며 메시지를 보내지 않습니다.

## 보안과 한계

- 화면 앱은 외부 네트워크 연결을 하지 않습니다. AI/외부 API/임베딩/원격 분석 기능이 없습니다.
- 대화·검색어·초안을 별도 파일이나 로그에 저장하지 않습니다. 터미널 스크롤백을 남기지 않도록 curses 대체 화면을 사용합니다.
- 최초 계정 확인 결과(숫자 계정 ID와 기존 계정 해시)만 `.state/account.json`에 저장합니다. 디렉터리 권한은 0700, 파일은 0600입니다. 비밀번호·DB 키·대화 내용은 들어가지 않습니다. 계정 해시가 바뀌면 재사용하지 않습니다.
- 원래 카톡 DB는 kakaocli가 읽기 전용으로 엽니다. 카톡 앱 자체의 네트워크 동작은 그대로입니다.
- subprocess에 셸을 사용하지 않습니다. 본문은 stdin으로 전달하므로 실행 인자에 넣지 않습니다.
- 받는 방 이름은 CLI 인자에 포함됩니다. 같은 사용자/관리자/보안 도구는 프로세스와 메모리에 접근할 수 있습니다.
- 대화에 포함된 제어문자와 ANSI escape를 그대로 터미널에 실행하지 않습니다.
- 전송에는 전체 방 목록을 이용한 ID/고유 이름 재검사와 수정된 kakaocli의 완전 일치를 사용합니다.
- UI 자동화의 최종 대상은 카톡 화면 이름으로 결정됩니다. 확인과 실행 사이에 방 이름을 바꾸지 마세요.
- 전체 디스크 접근과 접근성 권한은 범위가 넓습니다. 보안 검증/감사를 마친 공식 앱이 아닙니다.
- 메모리 덤프·터미널 세션 기록·화면 녹화·회사 단말 관리나 카톡 사용 기록을 숨기지 못합니다.
- 카톡 업데이트에 따라 DB나 UI 접근이 깨질 수 있습니다.
- 에이전트는 검증 중 실제 메시지를 보내지 않습니다. 사용자가 입력 후 Enter를 누르면 해당 방에 전송합니다.

## 동봉한 kakaocli 변경

원본 커밋: `8b6ffcfdaebc592a735dc1a8bd5e50037e626406` (MIT, 원본 라이선스는 `vendor/kakaocli/LICENSE`).

1. `send --exact`: DB에서 이름 고유성을 검사하고 UI에서도 완전 일치로 찾습니다.
2. `send --message-stdin`: 본문을 프로세스 인자 대신 표준입력에서 읽습니다.
3. `SHEETDESK_ACCOUNT_CACHE`: 현재 계정 해시와 일치하는 확인된 계정 번호를 재사용합니다. 원본의 10초 탐색 제한 문제를 피하고 매 폴링의 반복 탐색을 없앱니다.
4. `diagnostics`: 화면/본문을 출력하지 않는 읽기 전용 접근성 진단 및 전송 전 권한 검사.
5. `send --background`: 검증된 기존 창만 사용하고 자동 앱 활성화·창 열기·전역 키 입력을 하지 않습니다.
6. 백그라운드 입력 포커스 자동 지정 및 재확인. `diagnostics --prepare-input --chat "김 도완"`은 문자 입력·전송 없이 포커스만 준비합니다. 현재 맥에서 준비 성공과 전면 앱 유지 여부를 확인했습니다.

수정 없는 외부 바이너리는 읽기용으로 사용할 수 있지만, 해당 두 옵션이 없으면 전송을 거부합니다.

원본 수정 사항은 `kakaocli-sheetdesk.patch`로도 보관합니다. 동봉 소스가 없으면 setup.sh가 지정 커밋을 내려받고 패치를 적용합니다.

새 맥/다른 카톡 계정에서 계정 번호 자동 확인이 실패하면 다음 명령을 사용하세요.

```sh
./recover-account.sh        # 최초 1회 숫자 계정 ID 확인; CPU를 사용하며 수 분 걸릴 수 있음
./run.sh --doctor
```

확인은 본인 맥 카톡의 계정 해시를 대상으로 로컬에서만 수행합니다. 확인한 번호로 실제 DB 파일명을 검증한 뒤 저장합니다.
기본 탐색 범위는 0~10억 미만이며, 최신 계정 번호가 범위를 넘으면 `--max-id 4000000000`처럼 조정할 수 있습니다.

```sh
./run.sh --cli /path/to/kakaocli --readonly
python3 -B -m unittest discover -s tests -v
```
